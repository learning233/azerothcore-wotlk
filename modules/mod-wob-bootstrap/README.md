# mod-wob-bootstrap

WOB 全职业自动初始化与战场补给模块。不修改 AzerothCore 任何核心文件，
所有代码都在本目录内（`PlayerScript` + `DatabaseScript`）。

## 功能

- 所有账号新建角色自动 80 级（`OnPlayerCreate`）。
- 新角色初始自动装备四个 20 格霜纹包（`41599`），随建角保存。
- 新角色只保留主手、副手、远程／圣物三槽的初始装备，其余已穿装备直接销毁。
- 死亡骑士：创建/首次登录时把出生地任务（`QuestSortID=-372`；全表 59 个，按种族过滤后
  本角色 49 个）全部标记为已完成，补足 46 点任务天赋（80 级共 71 点）。只写完成标记，
  不发物品/金币/声望；死亡战马/黑锋之门等奖励法术由职业任务奖励技能逻辑学习。
- 首次登录自动：学完本职业训练师技能 + 职业任务奖励技能、急救/裁缝/工程 450
  （只学阶位法术，不学制造配方；成品补给的使用只查技能数值）、
  双天赋（`specsCount=2` + 63644/63645）、骑术四档学满到 300（33388/33391/34090/34091）+
  寒冷天气飞行（54197）、不自动点任何天赋。
- 每次登录：补满 6 种消耗品（`topup` 只补不删 / `exact` 扣到目标）、
  已装备鞋子自动附魔火箭靴（55016）、猎人宠物拉到 80 级；登录时由 AC 恢复上次退出时的出战宠物（`character_pet.slot=0`），不再补默认狼。
- 猎人宠物系统：兽栏保底 4 格；家族技能按官方 `LearnPetPassives` / `InitLevelupSpellsForLevel` 学习，玩家天赋触发的宠物技能不再白送；登录时清洗历史误授的跨系天赋，超标自动全额退款；支持重置出战宠物的天赋点数（兽栏中的不受影响）；每 30 秒自动检测并将宠物快乐度拉满（100 万，锁定 125% 伤害档位）。
- 盗贼武器涂毒系统：无需准备材料，支持通过命令或客户端换装面板一键为主手/副手武器附加 1 小时临时附魔（致伤药膏 VII / 致命药膏 IX / 速效药膏 IX / 减速药膏 / 麻痹药膏）。
- 隐藏聊天命令：`wob_glyph` / `wob_stable` / `wob_stable_refresh` / `wob_boots` / `wob_bootstrap` / `wob_reset_pet_talents` / `wob_reset_talents` / `wob_pet_adopt` / `wob_pet_abandon` / `wob_poison`
  （**不带点**：`.` 开头的消息会被 AC 内置命令系统先行消费，到不了模块钩子）。

## 逻辑说明

本模块注册三个脚本：世界脚本负责启动时改全局配置，数据库脚本负责建标记表并加载雕文对照表，
角色脚本负责建角、登录流水线和隐藏聊天命令。所有逻辑都在本目录内，不碰核心文件。

### 世界启动时改全局配置

每次世界服启动或重载配置时，世界脚本把全部 7 项耐久损耗系数改成 0，
同时打开无限弹药开关。效果是装备不再磨损，也不用手动改配置文件。
每次登录还会免费修一次存量损伤，之后不再掉耐久。

### 数据库加载时建表并读雕文表

数据库脚本在模块加载阶段做两件事：在角色库建 `mod_wob_bootstrap_done` 标记表
（记录每个角色跑完的版本号），从世界库读 `mod_wob_glyph` 表
（雕文编号到职业掩码的对照，由导出脚本生成）。
如果雕文表为空，只打警告并停用职业校验，槽位类型校验不受影响。

### 建角与出生背包

建角钩子负责升级、死亡骑士出生地任务和初始装备整理：等级不足 80 直接升到 80；
死亡骑士按种族过滤出生地任务分类（-372）全部标为已完成，
只写完成标记，不发物品、金币和声望，坐骑类奖励法术由后面的职业技能学习补上。
其余初始化不在建角时做，等登录时统一跑。

建角时直接销毁三栏武器以外的已穿装备，不占背包格。旧包先取出内容，再销毁并换成霜纹包；
原包内物品移到新包。整理完毕后保存，不影响现有角色。

### 登录流水线与版本号

登录流水线用版本号（当前为 4）加进程内集合做幂等：同一次运行只跑一遍，
已在标记表中达到当前版本的角色直接跳过。流水线顺序固定为：
升级、死亡骑士任务、骑术四档加寒冷天气飞行、坐骑法术、职业训练师技能加任务奖励技能、
三个专业拉满（只学阶位法术，不学制造配方）、开双天赋、武器技能补齐并拉满，最后存盘并写版本号。
强制重跑命令会跳过版本号检查，把整条流水线再走一遍。
骑术必须排在职业技能之前，否则需要前置骑术的职业坐骑学不上。
骑术和坐骑都用直接学会法术的方式，不走物品校验。

### 补货规则

补货只盯主背包 16 格，6 种物品各有目标数量。默认模式只补不删，
多出来的不收走；严格模式先按总量扣到目标再补。主背包塞得下就直接进包，
塞不下就按允许数量邮寄。带堆叠上限的物品按总量封顶，不会反复邮寄。
客户端消耗品栏同样只读主背包 16 格，两边口径一致。

### 猎人宠物

先明确 `character_pet.slot` 的取值：`0` = 当前出战宠，`1..4` = 兽栏槽位，`100` = 不在
兽栏槽里（AC 的 `PET_SAVE_NOT_IN_SLOT`）。本模块所说的“兽栏外/散落”指的就是
`slot = 100` 的宠物，对应内存里的 `PetStable::UnslottedPets`。

#### 兽栏槽位（固定免费 4 格）

- AC 原生 `characters.stable_slots` 默认是 `0`，需要玩家在兽栏管理员处花金币购买，最多
  4 格（`MAX_PET_STABLES = 4`）。本服不接 `CMSG_BUY_STABLE_SLOT`，由模块直接补满。
- 登录时、以及每次**打开/刷新兽栏**时，`EnsureStableSlots()` 检查
  `PetStable.MaxStabledPets`；小于 4 就设为 4，并执行
  `UPDATE characters SET stable_slots = 4 WHERE guid = ...`，内存和 DB 保持一致。
- 客户端兽栏面板固定显示 4 格；不提供金币购买入口。

#### “兽栏外”宠物（unslotted）自动归栏

- 登录时、以及每次**打开/刷新兽栏**时，`EnsurePetLevel()` 会扫描
  `PetStable::UnslottedPets`（猎人宠物，`slot = 100`）。
- 这些宠物的常见来源：
  1. 玩家主动解散/未召唤的宠物（法术 2641 `Dismiss Pet` → `PET_SAVE_NOT_IN_SLOT`）；
  2. 其它模块/历史数据直接写进 `character_pet.slot = 100` 的宠物；
  3. 异常数据或旧版本逻辑遗留。
- 处理方式：从槽位 1 开始找空槽，把 unslotted 猎人宠物依次搬进空槽
  `PetStable::StabledPets[i]`，同时执行
  `UPDATE character_pet SET slot = 1..4 WHERE owner = ... AND id = petNumber`，
  让内存 `PetStable` 和数据库一致，重登后不会丢位置。
- **槽满时不硬塞**：搬不进去的宠物保留在 `UnslottedPets`（DB 仍是 `slot = 100`），
  等玩家放生/腾出空位后的下次登录或开栏再收。旧逻辑会把这些没搬走的宠物从内存
  里错误删掉，已修。
- 只搬 `PetType = HUNTER_PET` 的宠物；其它类型的 unslotted 条目原样保留。
- 这是本服的便利逻辑，不是 AZ 原生行为。AZ 的 `SendStablePet` 在“没有当前宠物”
  时最多只显示 1 只 unslotted 作为 active，多只未归栏宠物在原生列表里会互相遮挡；
  自动收进空槽是为了让面板能看到全部宠物。

#### 等级 / 技能 / 快乐度 / 生命

- 登录时、以及每次开/刷新兽栏时，把该猎人**所有**宠物（当前、兽栏、unslotted）的等级
  同步到 80：先 `UPDATE character_pet SET level = 80 WHERE owner = ... AND PetType = 1`，
  再同步内存里的 `CurrentPet` / `StabledPets` / `UnslottedPets`，不重登也显示 80。
- 当前出战宠物会补学家族技能：按官方 `LearnPetPassives` / `InitLevelupSpellsForLevel` 学习，
  玩家天赋 aura 触发的宠物技能不再白送；登录/开栏时清洗历史误授的跨系天赋，超标部分自动全额退款。
- 快乐度：`OnPlayerUpdate` 每 30 秒检查一次，掉出最高档才补满；登录、驯服、开/刷新兽栏
  也会补满。客户端没有补快乐值的系统，服务端是唯一来源。
- 生命：只在**登录/驯服**时补满；开兽栏/刷新不再免费回血。
- 登录时由 AC `Player::LoadPet` 按 `character_pet.slot=0` 恢复上次退出时的出战宠物；没有宠物的猎人不再补默认狼，需要到兽栏图鉴驯服。

#### 驯服 / 存放 / 放生

- 驯服按官方逻辑：新宠直接成为**出战宠物**，不直接塞兽栏槽。
- 驯服时必须没有出战宠物或未归栏宠物：
  - 有出战宠物（含临时未召唤）→ 提示先存入兽栏；
  - 有未归栏宠物 → 提示先打开兽栏存入空位；
  - 存栏需要兽栏有空位，满格时提示先放生/取出一只兽栏宠物，或直接放生当前宠物。
- 校验与 AC 一致：必须是可驯服野兽（`IsTameable`）、特殊野兽需要兽王系终极天赋、
  模板必须有可用模型；死亡/战斗中拒绝。
- 放生只支持出战宠物；兽栏宠物必须先取出为出战宠物再放生。
- 另有重置出战宠物天赋、开兽栏、驯服和放生出战宠物命令。

### 雕文

插雕文时先查编号是否存在，再用数据字典里的槽位类型与请求槽位比对，
类型对不上直接拒绝；对照表里有职业掩码且非零时再校验职业。
替换旧雕文会清掉旧雕文的光环及其触发的衍生光环，再写新雕文并通知客户端刷新。

### 涂毒

涂毒仅限盗贼，先判职业再判战斗状态。目标槽只接受主手和副手，
且槽里必须是一把武器。六种输入对应五种 1 小时临时附魔和一种清除，
写在临时附魔位，不占永久附魔。客户端换装面板的涂毒入口同样只对盗贼显示。

## 部署（docker）

1. 把本目录（`server/mod-wob-bootstrap/`）整个拷到服务器仓库的
   `azerothcore-wotlk/modules/` 下（详见仓库根的 `server/DOCKER_UPDATE.md`）。
2. 在 `docker-compose.yml` 所在目录重新构建（**只支持 static modules**，不要用 `-DMODULES=dynamic`）：

   ```bash
   docker compose up -d --build
   ```

3. `data/sql/db-world/mod_wob_glyph.sql`（雕文职业校验表，`tools/export_glyphs.py` 生成）：
   worldserver 启动时 DatabaseUpdater 会自动应用模块 `data/sql/` 目录，无需手动导入。
4. 把 `conf/mod_wob_bootstrap.conf.dist` 复制到模块配置目录并按需修改
   （不放也能跑，代码默认值即全启用）。
5. 重启 worldserver。首次启动会自动在角色库建 `mod_wob_bootstrap_done` 标记表，
   并加载 `mod_wob_glyph`（未执行 SQL 时打 warning、职业校验禁用，槽位 TypeFlags 校验仍生效）。

## 命令表

| 命令 | 权限 | 作用 |
| --- | --- | --- |
| `wob_glyph <0..5> <glyphId>` | 所有玩家 | 插雕文（服务端校验槽位 TypeFlags + 职业 class_mask） |
| `wob_stable` | 所有玩家 | 开兽栏（施放 62757，aura 292 放行原生兽栏协议，2 分钟） |
| `wob_stable_refresh` | 所有玩家 | 续 62757 aura + 重发兽栏列表 |
| `wob_boots` | 所有玩家 | 立刻给当前鞋子附魔 Nitro Boosts |
| `wob_reset_pet_talents` | 猎人玩家 | 只重置出战宠物的天赋点数，全额返还（兽栏中的不受影响） |
| `wob_reset_talents` | 所有玩家 | 重置当前天赋方案的已分配点数（战斗中拒绝） |
| `wob_pet_adopt <entry>` | 猎人玩家 | 官方驯服：无出战/未归栏宠物时创建为出战宠物；有宠物先提示存兽栏（满格先放生/腾位） |
| `wob_pet_abandon <petNumber>` | 猎人玩家 | 只放生出战宠物（兽栏宠物需先取出） |
| `wob_poison <15\|16> <type>` | 盗贼玩家 | 为主手(15)或副手(16)涂抹 1 小时药膏（wound/deadly/instant/crippling/mind/clear） |
| `wob_bootstrap` | `SEC_GAMEMASTER` | 强制重跑核心初始化 + 补货 + 附魔 + 宠物 |

`wob_*` 前缀由 `OnPlayerCanUseChat` 吞掉不广播；`wob_wardrobe` 放行给衣柜模块。

## 已知限制

- 老 DK（已创建过的角色）在模块升级到 v4 后，任务行是登录时才写入的，而本次登录的
  任务天赋已经在 `LoadFromDB` 阶段统计完，所以**本次仍显示旧点数，再登录一次才变 71**。
  新建 DK 在 `OnPlayerCreate` 阶段就写入，首次登录直接 71。
- 未领取邮件不计入 `GetItemCount`：主背包长期满且不取邮件时，补货可能每次登录重复邮寄。
- `exact` 模式先按「背包+银行」总量扣到目标，再补主背包，可能短暂超过目标数量。
- save + marker 顺序依赖 `CharacterDatabase.WorkerThreads=1`（单 worker FIFO）；多 worker 部署需把
  两者放进同一事务。
- MaxCount 物品（43523=80）按总量上限补，已存银行/子包达到上限时主背包不再补。

## 回滚

- 配置级：`WobBootstrap.Enable = 0` 重启即停（不再初始化/补货）。
- 移除模块：删目录 + 重新构建镜像。
- 已被初始化的角色状态不会自动回滚（可用 GM 命令或删 `mod_wob_bootstrap_done` 行 / 把
  `BOOTSTRAP_VERSION` +1 触发重跑）。
